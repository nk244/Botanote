市場の植物・水やり管理アプリを調査し、本アプリ（Botanote）に足りない機能・実装したほうが良い機能を洗い出してIssueに登録する。

## 前提

- `gh` CLI が使用可能であること
- リサーチ・比較分析には **モデル Fable**（Agent ツールの `model: "fable"`）を使用する
- 引数（$ARGUMENTS）で調査観点を絞り込める（例: `/market-research AI機能` `/market-research 通知`）。指定がない場合は全般的な機能ギャップを調査する

## 手順

### ステップ1: 現状機能の棚卸し

以下を読み込み、Botanoteの現在実装済み機能を把握する:
- `CLAUDE.md` のプロジェクト概要
- `lib/screens/` `lib/providers/` `lib/services/` `lib/models/` のファイル一覧（画面・機能の網羅性確認）

### ステップ2: 既存Issueの取得（重複防止）

```bash
gh issue list --state all --limit 200 --json number,title,state
```

タイトル一覧を控えておき、後続のリサーチ・提案で重複させない。

### ステップ3: Fableモデルによる市場調査・ギャップ分析

Agent ツールを `model: "fable"`、`run_in_background: false` で呼び出す。
プロンプトには以下を必ず含める:

- Botanoteの概要と現状実装済み機能一覧（ステップ1の内容）
- 既存Issueタイトル一覧（ステップ2の内容、重複提案の禁止を明記）
- 調査対象: 市場で人気の植物・水やり管理アプリを最低4つ、WebSearchで調査する
  （例: Planta, Greg, Plant Parent, Blossom, PictureThis, Vera, Planti, GreenSnap 等。
  $ARGUMENTS で観点指定があればそれを優先する）
- 比較の観点: 水やりリマインダー以外の付加価値機能（AI診断・同定、季節調整、天気連動、
  ウィジェット、コミュニティ、成長記録、光量測定、統計など）
- 出力形式: 8〜10件に優先度（高/中/低）付きで、以下のテンプレートに従わせる

```
### [優先度] Issueタイトル案
**概要**: 1〜2文で機能を説明
**参考にした市場アプリ・機能**: どのアプリのどの機能を参考にしたか
**Botanoteへの実装イメージ**: 既存のどの画面/レイヤーに追加するか、簡単な実装方針
**優先度の理由**: なぜその優先度か
```

- ローカル完結型アーキテクチャ（サーバーレス・SQLite）と相性の悪い機能
  （サーバー同期が前提のコミュニティ/SNS機能など）は除外するよう指示する

### ステップ4: Issueとして登録

Fableの提案結果をもとに、各提案を GitHub Issue として登録する。

- タイトルは他Issueのトーン（簡潔な日本語の名詞句）に合わせて調整する
- 本文は以下の構成で一時ファイルに書き出し、`gh issue create --body-file` で作成する:

```markdown
## 概要
（機能の説明）

## 参考にした市場アプリ・機能
（調査結果）

## 実装イメージ
（影響するファイル・レイヤー、実装方針）

## 優先度
（高/中/低とその理由）

---
※本Issueは市場調査（モデル: Fable）に基づき自動作成。
```

- ラベル `enhancement` を付与する
- 一時ファイルはOSの一時ディレクトリに作成してよい（コミット対象にしない）

### ステップ5: 完了報告

作成したIssue番号とタイトルの一覧をユーザーに報告する:

```
## 市場調査に基づくIssue登録完了

- #<N> <タイトル>（優先度: 高/中/低）
- ...

調査対象アプリ: <調査したアプリ名一覧>
```

## 注意事項

- Issue登録は多いほど良いわけではない。既存Issue・既存機能と重複する提案は除外する
- 高優先度の判断基準: 競合アプリでの普及度、既存アーキテクチャでの実現容易性、ユーザー価値
- サーバー同期・コンテンツ運用が前提の機能（SNS、植物図鑑データベース等）はBotanoteのローカル完結方針と衝突するため、提案から除外するか低優先度とする
- **Issueを作成するのみで、実装やPR発行までは行わない**（実装する場合はユーザーの指示に基づき `/feature-design` を使う）
